# На чём основан подход

## Как детекторы ловят текст нейросетей

| Работа | Что измеряет | Что это значит для нас |
|---|---|---|
| GLTR (Gehrmann et al., 2019) | Ранги токенов в предсказаниях модели: у ИИ почти все слова из top-10 | Нужен «человеческий» гистограммный профиль рангов, а не просто редкие слова |
| GPTZero (Tian, 2023) | Perplexity + burstiness (разброс по предложениям) | Ритм «удивления» по предложениям важнее среднего |
| DetectGPT (Mitchell et al., 2023), Fast-DetectGPT (Bao et al., 2024) | Кривизна вероятности: текст ИИ вероятнее типичной выборки из модели | Наш текст должен лежать в «типичной» зоне, не выше и не ниже |
| Binoculars (Hans et al., 2024) | Отношение perplexity к cross-perplexity двух моделей | Подгонка под одну модель не переносится; оценивать надо панелью разных моделей |
| DivEye (Basani & Chen, 2025, [arXiv:2509.18880](https://arxiv.org/abs/2509.18880)) | Как колеблется «удивление» по тексту; устойчив к перефразированию | Нужно воспроизводить именно колебания, а не только уровень |
| Kobak et al., 2024 ([arXiv:2406.07016](https://arxiv.org/abs/2406.07016)) | «Избыточная лексика» LLM (delve, crucial, showcasing…) | Словарь штампов берём из данных, а не придумываем |
| Liang et al., 2023 | Детекторы ошибаются на текстах неносителей языка из-за низкой perplexity | Метрики шумные; нужна калибровка под жанр и автора |

## Как их уже пытались обходить

| Работа | Метод | Слабое место |
|---|---|---|
| DIPPER (Krishna et al., 2023) | Обученный перефразировщик | Детекторы нового поколения его ловят |
| Adversarial Paraphrasing (Cheng et al., 2025, [arXiv:2506.07001](https://arxiv.org/abs/2506.07001)) | Перефразирование под управлением детектора, минимизирует его оценку | Тянет текст в крайность; остаются стилистические следы |
| StealthRL (Ranganath & Ramesh, 2026, [arXiv:2602.08934](https://arxiv.org/abs/2602.08934)) | RL-обучение перефразировщика против 4 детекторов | Нужна тренировка модели; цель всё та же: «понизить счёт» |
| Attacks retain stylistic fingerprints (2025, [arXiv:2505.14608](https://arxiv.org/abs/2505.14608)) | Показывает: атаки оставляют стилевой отпечаток, особенно заметный на нескольких документах одного автора | Обход одного текста не равен обходу автора |

## Наша идея: подгонка под профиль, а не минимизация счёта

Существующие атаки **минимизируют** оценку конкретного детектора. Мы вместо этого **подгоняем распределение** под живой образец:

1. **Целевой профиль.** Строим статистический «отпечаток» по образцу человеческого текста. Лучше всего по текстам самого пользователя (несколько его прошлых работ), иначе по корпусу того же жанра и языка. Профиль включает: гистограмму рангов токенов (как в GLTR), распределение «удивления», его колебания по предложениям и автокорреляцию (как в DivEye и GPTZero), z-оценку Fast-DetectGPT, распределение длины предложений, частоты служебных слов и пунктуации.
2. **Варианты.** Claude генерирует несколько вариантов каждого предложения с разной степенью переработки.
3. **Выбор.** Поиск (beam search по предложениям) собирает текст, чей профиль ближе всего к целевому (расстояние Вассерштейна по распределениям) при сохранении смысла (эмбеддинги не ниже порога).
4. **Честная оценка.** Оптимизируем по одной модели, а проверяем другими (другое семейство, Binoculars-пара), чтобы не обманывать себя подгонкой.

Почему это сильнее: текст не уходит в крайность («слишком редкие слова»), которую ловят DivEye и стилевые детекторы, а попадает в зону, где живут настоящие тексты этого автора. Если профиль строится по текстам пользователя, его документы остаются согласованными между собой, а именно на этом ловит работа о стилевых отпечатках.

Насколько я нашёл, подгонку под авторский статистический профиль вместо минимизации счёта детектора в опубликованных работах не делали, но гарантировать полную новизну по беглому обзору нельзя.
