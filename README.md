# Хуманизатор текста (прототип)

**Офлайн-приложение для телефона и ПК** лежит в [docs/](docs/README.md): нейросеть работает прямо в браузере, без интернета после первой загрузки.

Переписывает текст так, чтобы его вероятностная статистика (perplexity, burstiness, доля «самых ожидаемых» токенов) меньше походила на типичный вывод LLM, при этом сохраняя смысл. Работает с русским и английским.

## Главный режим: подгонка под профиль автора

Идея и источники в [RESEARCH.md](RESEARCH.md). Коротко: вместо того чтобы «занижать оценку детектора», текст подгоняется под статистический профиль живого автора (лучше всего под ваши собственные тексты).

```bash
# 1. профиль по вашим текстам (несколько текстов в одном файле разделяйте двумя пустыми строками)
python -m humanizer profile my_texts.txt --out me.json
# 2. подгонка: Claude даёт варианты каждого предложения, поиск выбирает сочетание, ближайшее к профилю
python -m humanizer humanize draft.txt --target me.json -o out.txt --eval-lm Qwen/Qwen2.5-1.5B --report report.json
```

Профиль (`humanizer/profile.py`): гистограмма рангов токенов (GLTR), распределение «удивления», Fast-DetectGPT на токен, разброс и автокорреляция «удивления» по предложениям (GPTZero, DivEye), длины предложений, пунктуация. Поиск (`humanizer/search.py`): покоординатный спуск по выбору варианта для каждого предложения, минимизирует расстояние Вассерштейна до профиля, варианты с низким смысловым сходством отбрасываются. `--eval-lm` меряет результат другой моделью, чтобы видеть, не подогнан ли выигрыш под одну модель. Без `ANTHROPIC_API_KEY` варианты даёт локальная модель Qwen2.5-0.5B-Instruct (`--generator local-llm`, по умолчанию), то есть всё работает офлайн; `--generator local` даёт только замены слов и чистку штампов.

Веб-версия делает то же самое в упрощённом виде: блок «Образец вашего стиля» строит профиль по длинам предложений, пунктуации, однотипным началам и штампам, а варианты предложений даёт Claude.

## Как это устроено (базовый режим)

1. **Замер** (`humanizer/metrics.py`). Небольшая открытая модель (по умолчанию `Qwen/Qwen2.5-0.5B`) прогоняет текст и считает:
   - perplexity и долю токенов, совпавших с top-1 / top-10 предсказанием модели;
   - burstiness: разброс perplexity между предложениями и разброс длины предложений;
   - критерий **Fast-DetectGPT**: насколько текст вероятнее типичной выборки из самой модели (чем выше, тем «машиннее»).
2. **Claude-проход** (`--llm`, `humanizer/llm_rewrite.py`). Полное переписывание с инструкцией менять ритм, избегать штампов и выбирать менее очевидные, но естественные слова. `--llm-focus-rounds N` добавляет раунды, где Claude переписывает только самые предсказуемые предложения (их находит локальная модель). Нужен `ANTHROPIC_API_KEY`; модель `claude-opus-5-5` (можно сменить через `HUMANIZER_CLAUDE_MODEL`), включён серверный fallback на случай отказа модели.
3. **Структура** (`humanizer/structure.py`). Убирает типичные связки LLM («Важно отметить», «Кроме того», «Moreover», «delve»…) и меняет ритм: разбивает длинные предложения по союзам, склеивает короткие соседние.
4. **Лексика** (`humanizer/lexical.py`). Находит слова, которые модель предсказала как top-1 с высокой уверенностью, берёт у той же модели альтернативы в этой позиции, достраивает их до целого слова и принимает замену, только если:
   - остаток предложения остаётся почти таким же вероятным (грамматика и согласование не ломаются);
   - смысл сохраняется: эмбеддинги предложения и слова близки к оригиналу (`paraphrase-multilingual-MiniLM-L12-v2`).
   Без модели эмбеддингов этот шаг по умолчанию выключен: без проверки смысла модель охотно меняет «инструмент» на «риск».
5. **Контроль смысла по всему тексту**: если после шага сходство с оригиналом падает ниже 0.85, шаг откатывается.

## Запуск

```bash
pip install -r requirements.txt

# только замер
python -m humanizer measure examples/ru_ai.txt

# переписать (локально, без Claude)
python -m humanizer humanize examples/ru_ai.txt -o out.txt --report report.json

# с Claude-проходом и двумя прицельными раундами
export ANTHROPIC_API_KEY=...
python -m humanizer humanize examples/en_ai.txt -o out.txt --llm --llm-focus-rounds 2
```

Опции: `--lm` (другая модель для замеров, HF id или локальный путь; для русского лучше модели с хорошим русским, например Qwen2.5-1.5B), `--strength` (доля слов под замену, по умолчанию 0.12), `--embed none`, `--no-structure`, `--no-lexical`, `--seed`.

## Важные оговорки

- Метрики считает та же модель, что направляет лексические замены, поэтому улучшение по ней частично «подогнано» под неё. Настоящие детекторы используют другие модели, и эффект переносится не полностью. Честная проверка: мерить другой моделью (`--lm` в `measure`) или внешним детектором.
- Claude-проход даёт основной выигрыш по естественности; статистические шаги доводят цифры.
- В облачном окружении проекта huggingface.co пока закрыт, поэтому код проверен на самодельной мини-модели (проверка, что всё работает), а реальные цифры «до/после» ещё не сняты.
